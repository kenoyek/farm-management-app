# Scientific data validation

All workbook nutritional data starts UNVERIFIED. Workbook provenance alone does not establish scientific authority. Preserve original cells and never guess corrections. Numeric plausibility checks are issue detectors, not scientific validation.

## Required review
A qualified nutritionist must approve species, strain/stage, nutrient system (ME vs DE, total vs available/digestible phosphorus and amino acids), as-fed vs dry-matter basis, units, ingredient processing restrictions, anti-nutritional factors, laboratory dates, inclusion bounds and profile references. Fish generic rows do not define African catfish requirements. Zero price may be a missing quotation, not free material; positive historical prices are still stale. Mineral/premix blank nutrients cannot be assumed zero. Source concentrate product specifications and label rates must match the actual purchased product.

Quarantine Dietary Needs I30=47/I36=22, Intake G12=10/H24=28.8/I24=63 and all alias mismatches. Do not “correct” them by moving decimal places. Defatted soybean methionine is absent: manual recipe methionine totals from the workbook are incomplete even when numeric cached results exist. Dry matter zero is a workbook formula omission, not a biological observation.

## Source hierarchy and traceability
Prefer product laboratory certificates and official strain feeding guides (current Ross/Cobb broiler and Hy-Line/ISA layer guides), then authoritative references such as NRC Nutrient Requirements of Poultry, NRC Nutrient Requirements of Fish and Shrimp, FAO aquaculture guidance and validated ingredient composition databases (e.g. Feedipedia). These are candidate references, not sources already independently verified in this task. Record publication/version/page, species, unit/basis, analyzer date, reviewer identity and approval date. Do not copy generic requirements into approved profiles without review.

## Workflow
Upload original → immutable hash → staged extraction → structural/unit/price/alias issues → preview → confirmed import as unverified → source/lab reconciliation → nutritionist-reviewed ingredient and requirement versions → solver eligibility → formula review → immutable approval → batch mixing. Changes to prices/ingredients create new scenario/formula versions. Manufacturing release requires all required data complete/current and approved, 100% inclusion, safe bounds and nutrient compliance; a solver optimum alone is insufficient.

Forecast mortality, rations, laying rates, fish feeding/water-quality thresholds and growth assumptions must be explicit and editable. Forecasts are estimates, never veterinary diagnoses. Flag representative sampling limits and water/temperature effects. Keep operational observations separate; preserve historical model/input versions.

Implemented review gates additionally require declared species/stages, phosphorus basis and price quotations within 90 days. The 90-day window is a first-release freshness policy, not scientific evidence that a price is current. Stored ingredient inclusion bounds cannot be relaxed by scenario overrides. Available-kg bounds may further restrict an optimization; blank availability explicitly means an unconstrained planning scenario. There is no manufacturing release or physical-stock reservation workflow yet. Poultry requirements and ingredients must match species, stage, energy, nutrient and phosphorus bases. Dedicated catfish digestible nutrient definitions are not implemented, so catfish formulation is rejected rather than borrowing poultry standards.


Reviewed profiles may now declare an explicit allowed list of ingredient reference UUIDs with stage-specific inclusion minima/maxima and per-rule evidence. Required ingredients cannot be omitted, and new quotations/revisions need explicit profile review before replacing a listed reference. An empty rule list carries no profile-specific ingredient authorization; it retains the original reviewed-ingredient selection checks. Stored global ingredient bounds still apply and cannot be weakened by the profile, scenario or solver. Profile revisions preserve historical evidence; new recipe/optimizer snapshots record the chosen version. These percentage rules do not constitute a processing-method, anti-nutritional-factor or manufacturing safety model. No workbook restriction becomes approved automatically.


Source catalog identity reconciliation is an explicit assigned-nutritionist decision for one immutable row/context. A mapped decision selects an exact ingredient revision with evidence; rejection/unresolved decisions select no ingredient. It neither approves nutrient values nor interprets missing/scalar inclusion constraints. No match is inferred by name, formula reference or ingredient lineage, and revisions do not inherit mappings. Raw alias warnings remain visible after review. Qualification and the evidence supporting real decisions remain the organization's responsibility; implementation test fixtures do not constitute scientific catalog review.


The eleven-field registry adds crude fat, crude fibre, as-fed moisture and ash as independently supplied measurements, not derived estimates. The existing reference basis applies to crude fat/fibre/ash; moisture is always an as-fed percentage and is rejected on dry-matter references/profiles. No 100-minus-dry-matter conversion occurs. Generic source lipids/cellulose are not mapped to crude fat/fibre assays automatically. Explicit workbook header suggestions still require preview/confirmation and remain unverified. Optional fields without reviewed limits are unassessed; adding a limit requires measured values for every included/solver-selected reference. Missing assessed values block approval/optimization. This does not add digestible amino acids, NDF/ADF methods or a catfish nutrition model.


Reference category, supplier, laboratory date, certificate reference and processing notes are supplied evidence, never automatic qualification. A laboratory date is not inferred from the review/quotation date; no unreviewed laboratory freshness threshold or processing rule is invented. Source-recipe confirmation requires explicit mapped identities for populated rows, plus acknowledgement of omitting unspecified inclusions. All 34 original rows and warnings remain recorded. The result is always a draft without a reviewed profile or release eligibility, even when all selected references are approved. Cached source nutrient totals and ambiguous stage restrictions are ignored. A new reviewed recipe must pass current reference, quotation, basis, profile and nutritionist checks separately.


Structured processing constraints now distinguish a recorded reference method from manufacturing activity. A method identifier requires paired evidence; quality notes and ingredient names never supply it. Nutritionists may review exact-reference groups with explicit aggregate inclusion bounds and optional required methods, all within a closed allowed list. Unknown/mismatched required methods block review; manual and optimized allocations must satisfy the group bounds independently of nutrient checks. No treatment parameters, heat effectiveness, anti-nutrient concentrations or safe maxima are inferred. Recording a method does not prove treatment of a purchased lot, and passing a numerical group constraint does not certify manufacturing safety. Physical process/assay qualification remains separate work.
